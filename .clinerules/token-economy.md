# Экономия токенов, аудит и reasoning level (FRAME)

## Reasoning level
- По умолчанию — **medium**. `low`/`none` — правки по образцу, тексты, переименования.
  `high` — только неочевидный баг, многофайловая логика, архитектура. `xhigh` — только
  критическая безопасность/миграция с риском потери данных. Не завышать.
- В конце ответа — **одна строка**: `Следующий шаг: … · reasoning: medium`.
  Полный блок (шаг / уровень / обоснование) — только если владелец попросил или это
  архитектурное решение: сам блок тоже расходует токены в каждом ответе.

## Аудит
- Сначала согласуй объём: «читаю файлы X, Y — исключить что-то?». Не читать проект целиком.
- Один модуль за проход; отчёт — в файл, в чат — вердикт ≤10 строк.
- «Попутно исправил» запрещён: аудит = только отчёт.

## Чтение и вывод (самое дорогое)
- Файлы >100 КБ (`Materials.tsx`, `Objects.tsx`) — только диапазоны строк и `Select-String`,
  не читать целиком.
- Не дублировать в ответе код, который уже в файле — ссылка `файл:строка`.
- Не перечитывать файл, который уже читался в этой сессии; искать по нему грепом.
- Отчёты, диффы, таблицы — в файл, а не в чат.
- Не читать `node_modules`, `dist`, `.git`, `*.log` без прямой просьбы.
- Не запускать повторный полный аудит ради «второго мнения»: второе мнение — только там,
  где решение стоит денег (права, платежи, деплой).
