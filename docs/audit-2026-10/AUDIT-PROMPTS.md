# FRAME — промпты аудита (27.10.2026)

Как пользоваться: **один промпт = один новый чат Cline** с указанной моделью, в том же
воркспейсе `C:\PROJECTS\frame-app`. Промпты самодостаточные (новый чат ничего не помнит).
Каждый агент пишет ОДИН отчёт в `docs\audit-2026-10\<буква>-<тема>.md` и ничего больше не меняет.

Готовые к копированию файлы (этот документ — мастер, они вырезаны из него):
`docs\audit-2026-10\prompts\A-access.txt`, `B-design.txt`, `C-predeploy.txt`, `D-hosting.txt`,
`E-rustore.txt`. Открыть файл → скопировать ВСЁ → вставить в новый чат с нужной моделью.

**Перед запуском (обязательно):** закоммитить текущий пакет №175–№179 (в дереве 25 изменённых
файлов). Иначе агенты аудируют плавающее состояние, а твои правки перемешаются с их отчётами.
Проверка: `git status --short` = пусто; `git rev-parse --short HEAD` — записать хеш в отчёты.

**Волна 1 (параллельно, 3 чата):** A (DeepSeek V4.1 Pro), B (GLM 5.3), D (Qwen 3.8 Max).
**Волна 1.5 — второй взгляд на главное:** A₂ — тот же `A-access.txt` в чате с **Kimi K3.1 Pro**,
независимо (отчёт A не читать до конца прогона). Расхождение вердиктов = место, где решение по ролям
принимать нельзя без третьей проверки руками.
**Волна 2:** C (Qwen 3.8 Max — последовательно с D, не одновременно), E (GLM 5.3 Flash — можно в волне 1).

**Почему DeepSeek V4.1 Flash не аудирует (важно):** он ведёт этот чат, то есть уже знает репозиторий,
гипотезы и историю правок — его «аудит» будет подтверждением собственных допущений, а не поиском.
Плюс он же будет исполнять правки по отчётам: судья и исполнитель в одном лице находит только то,
что удобно исправлять. Его роль — свод отчётов, проверка каждой находки по файл:строка, срезы №180+.


**Не запускать:** повторный аудит того, что уже решено владельцем (§24): дубли материалов 291/292
не удалять, push-уведомлений о заявках нет, шаблон объекта без дат и `catalogId`, согласования
(п.1 «б») — это открытое решение, а не дефект.

5) МЁРТВОЕ. Подтверди фактом (grep, число ссылок) статус ChangeRequest: API /change (GET project/:id,

   не оставляем». Дай 3 варианта решения с ценой: (а) доделать UI, (б) выключить и удалить код+модель

6) ОЦЕНКА СЛОЖНОСТИ ДЛЯ ВЛАДЕЛЬЦА (главный вопрос аудита). Ответь числом и по делу:

   - сколько файлов надо править, чтобы добавить новую роль или новый флаг;
   - какие 3–5 флагов реально дублируют друг друга и какие можно схлопнуть без потери поведения.

ФОРМАТ ОТЧЁТА (docs\audit-2026-10\A-access.md):
- шапка: хеш коммита (`git rev-parse --short HEAD`), дата, модель;
- таблица находок: 🔴 блокер / 🟡 средне / 🟢 мелочь | файл:строка | суть | почему это проблема |

напиши); не предлагать новые фичи; вердикт важнее полноты — лучше 15 точных находок, чем 60 общих.
В чат в конце: 10 строк — вердикт, топ-3 риска, топ-3 упрощения, твоя рекомендация по п.1 (а/б/в).
