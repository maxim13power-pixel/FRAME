## 0. TL;DR

Черновик §12 **подтверждён фактами и остаётся в силе**: переезжаем на **Amvera** (регион Москва),
связка fe 290₽ + be 490₽ + PG 490₽ = **1 270 ₽/мес** (потолок бюджета 1 600 ₽/мес), срок — **1 рабочий
день** (окно 2–4 ч) + неделя наблюдения. Три уточнения к черновику: (1) «потолок 6 ГБ RAM» устарел —
есть Ультра Плюс 9 ГБ/7 750₽; (2) расписания бэкапов PG **отключаются после остановки кластера** —
надо реактивировать; (3) исходящий SMTP 465 с Amvera **документирован официально** (инструкция n8n),
но финальное подтверждение — только тестовым письмом. Главный риск переезда — не платформа, а
**доступность данных на Railway прямо сейчас** (проект не отвечает, триал до ~28.10.2026).

## 4. Варианты — факты и цены (все проверки 27.10.2026)

### 4.1 Amvera (PaaS, ООО «АМВЕРА», Москва/Амстердам/Майами) — базовый вариант черновика

- **Тарифы приложений** (price.html): Пробный 170₽ (0,1 CPU/100 МБ/2 ГБ); Начальный 290₽ (0,25/500 МБ/5 ГБ);
  Начальный Плюс 490₽ (0,5/1 ГБ/7 ГБ — **с него бэкапы и расширенный мониторинг**); Стандартный 1450₽
  (1/2,5 ГБ/15 ГБ — приоритетная поддержка); Ультра 4300₽ (2/6 ГБ/25 ГБ); Ультра Плюс 7750₽ (3/9 ГБ/35 ГБ).
  Поминутная тарификация, списание раз в час; диск сверх тарифа — 35₽/ГБ/30 дней; остановленный проект не списывается.
- **Тарифы СУБД** — та же сетка от «Начальный» 290₽; стабильная работа PG — не ниже «Начальный»; реплики — отдельно.
- **PG-бэкапы**: бесплатно 3 последних по расписанию + 3 ручных; **PITR нет**; restore → **новый кластер**
  (менять DATABASE_URL; пользователь/пароль восстанавливаются); после остановки кластера расписание отключается.
- **Версия PostgreSQL**: в доках не указана → **подтверждение владельца** (нужна ≥15 под дамп Railway).
- **Сеть**: бесплатный домен 3-го уровня с HTTPS (Let's Encrypt) на каждое приложение; свой домен —
  входной контроллер nginx + SSL бесплатно; внешний доступ к PG — домен типа POSTGRES (`…db-msk0.amvera.tech`,
  SSL prefer); TCP-порты 5432/27017/6379 открыты. **С 26.09.2026** входящий трафик — тарифные планы
  (по регионам): лимиты размера запроса/ответа, таймаута, соединений, RPM; по умолчанию бесплатный план
  с лимитами (цифры — только в ЛК, таблица в доках картинкой). Мониторинг входящего трафика бесплатен.
- **SMTP**: исходящий 465+SSL документирован (инструкция n8n на docs.amvera.ru) → вероятно работает;
  финал — тест письмом. HTTP-API-почты у платформы нет → fallback Yandex Cloud Postbox (§4.3).
- **Деплой**: Git (GitHub/GitLab/Bitbucket) + `amvera.yml` (Node 20/22) или Dockerfile; `run.command`
  произвольная (наша — `npm run start:prod`); постоянный диск `/data`; серверы в UTC; логи в ЛК,
  с «Начального Плюс» — расширенный мониторинг.
- **Смета**: минимум fe 290 + be 490 + PG 290 = **1 070₽/мес**; рекомендуемая fe 290 + be 490 + PG 490 =
  **1 270₽/мес**; «×2»: fe 290 + be 1450 + PG 1450 = **3 190₽/мес** (статика не масштабируется по RAM).
- **Лок-ин**: низкий — Git-репо свой, PG-дамп выгружается через внешний домен; специфика — `amvera.yml`
  (5 минут на замену) и домены amvera.tech (меняются на свои).

### 4.3 Yandex Cloud (ООО «Яндекс.Облако»)

- **Managed PostgreSQL** (прайс, действует с 30.04.2026): vCPU Intel Ice Lake 100% — 1,8792₽/час;
  RAM — 0,5072₽/ГБ·час; network SSD — 0,0218₽/ГБ·час; бэкапы сверх хранилища — 0,00307₽/ГБ·час;
  публичный IP — 0,2766₽/час (~202₽/мес). Классы хостов: создание кластеров с гарантированной долей
  vCPU <100% (**b1/b2/b3**) **больше недоступно**; минимальная рекомендуемая прод-конфигурация —
  2 vCPU 100%; s-серия (4:1) → минимум **2 vCPU/8 ГБ**.
  **Расчёт минимума**: 2×1,8792×730 + 8×0,5072×730 + 10 ГБ×0,0218×730 ≈ 2 744 + 2 962 + 159 =
  **≈5 865₽/мес за ОДНУ PG** (без IP). Это в ~4,6 раза дороже всего стека на Amvera.
- Бэкапы/restore из бэкапов есть; Datatransfer для миграции; SLA с компенсацией (по обзору Amvera — 50%
  месячных затрат). Исходящий трафик: 100 ГБ/мес бесплатно, далее 1,42₽/ГБ.
- **PaaS «из GitHub» нет**: Serverless Containers / VM / Managed Containers (k8s) — для одного админа
  это DevOps-нагрузка (подтверждает §1: «дорого/сложно»).
- **Object Storage** (для статики): STANDARD ≈2,376₽/ГБ·мес (первый 1 ГБ бесплатен); GET — 3,13₽/1000
  (первые 100 000/мес бесплатны); PUT — первые 10 000 бесплатны; исходящий трафик 100 ГБ бесплатно,
  далее ~1,68₽/ГБ. Пример из доков: сайт 3 ГБ + 120 000 запросов/мес ≈ **67₽/мес**.
- **Postbox** (SMTP-замена по HTTP API, AWS SES-совместим): первые **2 000 писем/мес бесплатно**,
  далее 80,32₽/1000 (2 001–10 000); регион РФ; цены с 30.04.2026. Подходит как fallback почты с любой платформы.
- **Яндекс 360 для бизнеса**: тариф «Минимальный» — **319₽/сотрудник/мес** (почта на домене, 100 ГБ Диска) —
  уже используется (SMTP smtp.yandex.ru 465 для `noreply@frame-app.ru`); «Почта и файлы» — 279₽/сотр./мес от 10 сотр.
- **Вердикт**: для нашей нагрузки неоправданно дорого (PG ≈5 900₽/мес) и сложно; но Postbox и 360 —
  оставляем как почтовый контур.

- **Cloud Databases** (docs): тарификация vCPU/RAM/диск pay-as-you-go; **не тарифицируются: автоматические
  резервные копии, входящий/исходящий трафик, мониторинг**; конфигурации Single / Master-Replica / Кластер
  (Patroni, авто-failover); PostgreSQL поддерживается. Минимальный Single-инстанс (1 vCPU/1 ГБ + 10–20 ГБ
  High-IOPS) по прайсу ≈ **1 200–1 500₽/мес (расчёт)**. Новым аккаунтам — 5 000₽ на 60 дней (marketing).
- **PaaS из GitHub нет** (Managed Containers = k8s — избыточно); для be/fe — VM своими руками (Docker+Caddy).
- **SMTP**: документально не проверен → уточнять.
- **Вердикт**: дешевле Yandex, сильнее по 152-ФЗ/ФСТЭК, но DIY-администрирование → не для одного человека без DevOps.

### 4.5 Selectel (АО «Селектел», лицензия телематических услуг №176267)

- **VPS/VDS — «от 200₽/мес»** (marketing-страница; конфигурации в калькуляторе); облачные серверы pay-as-you-go;
  **3 ТБ внешнего трафика бесплатно в месяц** на аккаунт; базовая DDoS-защита включена; 152-ФЗ.
- **Облачные базы данных (Managed PG/MySQL/Redis/TimescaleDB) — от 2 685,02₽/мес** (marketing); бэкапы автоматические.
- **S3 — «от 1,12₽/мес»** (формулировка marketing; цена за ГБ — в калькуляторе); резервное копирование в облаке от 3,66₽/мес.
- **SMTP**: исходящие **25/465/587 заблокированы** (docs/infrastructure/blocked-ports); разблокировка —
  только тикетом, «не можем гарантировать», **для VDS-серверов — невозможна**; рекомендуют свой почтовый сервис.
- **Вердикт**: хорошая инфраструктура, но managed PG от 2 685₽ + SMTP-риск → мимо для нашего бюджета.

### 4.6 Классический VPS + Docker + Caddy + pg_dump по cron (Timeweb/reg.ru/VDSina/aeza)

- Проверенный минимум: **Timeweb MSK Ultra 15 — 1 920₽/мес** (1 vCPU/1 ГБ/15 ГБ NVMe/1 Гбит/с, IP включён) —
  1 ГБ на NestJS+PG+Node впритык → реально нужен Ultra 30 (2 ГБ) за **3 000₽/мес**.
- Цены reg.ru/VDSina/aeza на дату проверки официальными источниками **не подтверждены** → в расчёт не беру
  (не выдумываем тарифы).
- SMTP: порты блокируются по умолчанию, разблокировка из панели (Timeweb) — подтверждено доками.
- **Вердикт**: при проверенных ценах DIY-VPS **не дешевле** PaaS (3 000₽ против 1 270₽) и добавляет
  DevOps-нагрузку (Docker, Caddy, certbot, cron pg_dump, обновления ОС, fail2ban). Не рекомендую.

### 4.7 Статика отдельно: объектное хранилище / бесплатный CDN

- **Yandex Object Storage**: технически возможно (статический сайт в бакете, ~67₽/мес на 3 ГБ/120k запросов),
  но SPA history-fallback и HTTPS-домен требуют ручной обвязки; дешевле и проще отдать fe платформе
  (Amvera 290₽ или Timeweb Frontend ~25–50₽).
- **Selectel S3**: аналогично, цена за ГБ уточняется калькулятором.
- **Бесплатный CDN (Cloudflare и т.п.)**: иностранные юрлица, деградация доступности из РФ в 2024–2026,
  оплата/аккаунты нестабильны → как критический элемент **не рекомендую**; максимум — резерв DNS.
- **Вывод**: статику держим на той же платформе, что и be (один контур, один биллинг, CORS без сюрпризов).

### 4.8 RuStore Cloud — проверка

**Собственного облачного хостинга у RuStore нет** (проверено 27.10.2026): RuStore — магазин Android-приложений
(консоль разработчика, аналитика, модерация); инфраструктурные сервисы разработчикам RuStore даёт
**через партнёрскую программу VK Cloud** (docs.rustore.ru/rustore-analytics/tools; rustore.ru — программа
поддержки с VK Cloud). Для нашего веб-приложения неприменим; если понадобится — это фактически VK Cloud (§4.4).

## 6. Рейтинг и итоговая рекомендация

**Топ-3:**
1. **Amvera** — единственный вариант, где весь стек (fe+be+PG) укладывается в 1 070–1 270₽/мес при
   полном соответствии критериям: git-деплой, managed PG с бесплатными бэкапами, SMTP 465 документирован,
   бесплатный SSL/домены, юрлицо РФ, регион Москва, поминутная тарификация (можно щупать за триал-баланс).
2. **Timeweb Cloud (App Platform + DBaaS)** — сильный №2: официальная поддержка NestJS (run-команда по
   умолчанию — ровно наша), PG **15 гарантированно** (14–18), логические бэкапы-дампы скачиваются из S3
   (готовый offsite), SLA 99,98%, ПО в реестре. Минусы: цена backend не опубликована (смета только в ЛК),
   SMTP для App Platform не подтверждён, автобэкапы платные (6₽/ГБ), PITR не подтверждён.
3. **VK Cloud** — лучший «корпоративный» запасной: автобэкапы DBaaS бесплатны, 5 000₽ грант, ФСТЭК/152-ФЗ,
   дёшево по ресурсам; минус — нет PaaS, всё руками (VM+Docker), SMTP не проверен.

**ИТОГОВАЯ РЕКОМЕНДАЦИЯ:** переезжаем на **Amvera**, регион **Москва**, конфигурация:
**frontend — «Начальный» (290₽), backend — «Начальный Плюс» (490₽), PostgreSQL — «Начальный Плюс» (490₽)**,
бюджет **1 270 ₽/мес** (потолок с резервом на платный тариф входящего трафика и диск — **1 600 ₽/мес**),
срок переезда — **1 рабочий день** (окно 2–4 ч) + 3–7 дней наблюдения.
**Условие (гейт G0):** до оплаты подтвердить в поддержке/ЛК Amvera: (а) версия PostgreSQL ≥15;
(б) лимит размера запроса бесплатного тарифа входящего трафика ≥20 МБ (Excel/будущий импорт);
(в) тестовое письмо SMTP 465 на `noreply@frame-app.ru`. Если (а) не выполняется — **план Б: Timeweb Cloud**
(App Platform fe+be + DBaaS PG 15 от 790₽), если (в) — почта через Yandex Cloud Postbox (HTTP API, 2000 писем бесплатно).

**Если бюджет 0 и готов возиться:** бесплатного хостинга под весь стек нет (триал Amvera ~170₽/мес баланса —
единственный «почти ноль»). DIY-VPS по проверенным ценам **дороже** PaaS (Timeweb Ultra 30 = 3 000₽/мес
против 1 270₽) и требует DevOps; дешёвые VPS (200–500₽) у reg.ru/VDSina/aeza на дату аудита официально
не подтверждены — если владелец найдёт такой тариф: Ubuntu 22.04 + Docker (be, fe-статика через Caddy) +

## 7. План переезда (проверка и развитие шагов §12)

**Окно работ:** вечер 19:00–23:00 МСК, 2–4 часа; пользовательская нагрузка минимальна.
**Что владелец делает руками:** регистрация/оплата Amvera, ответы поддержки (гейт G0), DNS в панели
регистратора (reg.ru), тестовое письмо, финальное «добро» на переключение DNS.

**G0 — проверки ДО всего (день 0):**
1. Поддержка Amvera: «какая версия PostgreSQL в managed-кластерах?» → нужно ≥15 (иначе план Б Timeweb).
2. ЛК → Настройки → Сеть: лимиты бесплатного тарифа входящего трафика (макс. размер запроса/ответа,
   таймаут, RPM) для Москвы; цена платных тарифов. Нужно: запрос ≥20 МБ (Excel сейчас генерится на
   клиенте, но импорт RFC-import-estimate и фото-фиксация — будущие upload'ы).
3. Тест SMTP: после шага 5 отправить письмо nodemailer (smtp.yandex.ru:465, SSL) на личный ящик.
4. **Спасение данных (критично, не ждать окна!):** Railway не отвечает → попробовать: (а) dashboard
   Railway → Backups; (б) тикет в Railway support с просьбой снять дамп/восстановить доступ;
   (в) если появится доступ — `pg_dump -Fc` немедленно, хранить локально + в Яндекс Диск.

**Шаги (день 1, окно):**
1. **Дамп:** `pg_dump -Fc -U <user> -d <db> -f frame_20261027.dump` через внешний доступ Railway
   (или из Backup'ов Railway, если доступ так и не появился). Проверить размер и `pg_restore -l`.
2. **PG Amvera:** создать кластер PostgreSQL, Москва, тариф «Начальный Плюс» (490₽), включить
   Superuser (`postgres`) — пригодится для restore; включить расписание бэкапов СРАЗУ.
3. **Restore:** `pg_restore -d <db> --no-owner --no-privileges frame_20261027.dump` через внешний
   POSTGRES-домен (`…db-msk0.amvera.tech`, sslmode=prefer). Сверить число таблиц/строк ключевых моделей
   (User, Object, Project, Material, FixedAt) с дампом.
   - **Если restore упал:** (а) «unsupported version» → версия PG-target < 15 → стоп, план Б Timeweb;
     (б) ошибки прав/owner → `--no-owner --no-privileges`; (в) конфликты объектов → `--clean --if-exists`;
     (г) encoding/locale → пересоздать БД с UTF8; (д) висит >20 минут → поддержка Amvera (по докам).
4. **Миграции:** `npx prisma migrate deploy` с локали через внешний домен (DATABASE_URL c
   `?sslmode=prefer`). Ожидание: «No pending migrations» (дамп уже содержит схему). Если Prisma ругается
   на TLS (нюанс §2.4) → `sslmode=require`, свежий Prisma CLI.
5. **Backend:** проект Amvera из GitHub (monorepo, директория `backend`), `amvera.yml`: Node 22,
   `run.command: npm run start:prod`, containerPort/servicePort 3000; env: `DATABASE_URL` (внутренний
   домен `…cnpg-…-rw`), `JWT_SECRET`, `CORS_ORIGINS=https://frame-app.ru`, `FRONTEND_URL=https://frame-app.ru`,
   капча, SMTP (`smtp.yandex.ru`, 465, SSL, `noreply@frame-app.ru`). Smoke на бесплатном домене
   `*.amvera.tech`: health, login, дашборд (агрегаты!), экспорт Excel/PDF, **тест-письмо**.
   Следить за RAM в мониторинге (пик агрегатов < 1 ГБ → остаёмся на 490₽; иначе «Стандартный» 1450₽).
6. **Frontend:** проект из GitHub (директория `frontend`), тариф «Начальный» (290₽); **перед билдом**
   задать `VITE_*` (API=https://api.frame-app.ru) в env приложения Amvera — переменные впечены в билд;
   раздача статики (их nginx либо Dockerfile c `serve -s dist`); smoke на бесплатном домене.
7. **Restore drill (прод НЕ трогаем):** на PG создать ручной бэкап → «Восстановить» → поднимется
   НОВЫЙ кластер → подключить DBeaver/pgAdmin ≤8.12 → проверить 3–5 ключевых таблиц → прогнать 2–3
   тяжёлых запроса дашборда, замерив время и RAM → **удалить** новый кластер. Закрывает п.14 чек-листа
   (§11 PROJECT_STATUS.md) и риск №3. После drill — проверить, что расписание бэкапов активно.
8. **DNS (владелец, reg.ru):** `frame-app.ru` → домен fe (по инструкции ЛК Amvera: TXT-подтверждение +
   A/CNAME), `api.frame-app.ru` → домен be. Дождаться выпуска SSL (~10 мин; домен только в нижнем регистре).
9. **Прод-smoke:** health, login, дашборд, экспорт, письмо, CORS (консоль браузера), создание/правка
   объекта (запись в БД).
10. **Параллельная работа 3–7 дней:** Railway сейчас лежит → параллельность условна: держим Railway
    (если оживёт) как rollback-контур с прежним DATABASE_URL; на Amvera ежедневно: проверка бэкапов,
    RAM/диска, мониторинг входящего трафика. **DNS не поднимаем до зелёного drill (шаг 7)** — по §12.
11. **Отключение:** через 3–7 дней стабильной работы — остановить Railway (данные в US — удалить после
    финального дампа-архива), зафиксировать в PROJECT_STATUS.md новую платформу.
12. **Offsite-бэкап (сразу после переезда):** weekly `pg_dump -Fc` через внешний домен → локально +
    Яндекс Диск (ретенция Amvera — всего 3 копии; см. риск №5).

  ИП/ООО для приёма платежей через приложение не требуется; для B2B-договоров с подрядчиками и
