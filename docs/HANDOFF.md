## Что это
Учёт стройки: объекты → сметы (проекты) → материалы → склад → бригады (выходы/часы/сделка) →
аналитика и отчёты. Роли: `OWNER`, `MANAGER`, `FOREMAN` (прораб), `STORE_MANAGER`, `VIEWER`.
Плюс наблюдатели — доступ к объекту через `object_access` с флагом `hidePrices`.

Стек: NestJS 11 + Prisma 6 + PostgreSQL 18 (docker, порт **5433**), React 19 + Vite + MUI
(порт **5000**), бэкенд — **3000**.

## Как запускать
```
docker compose up -d                     # БД на 5433
npm --prefix backend run start:dev       # API :3000 (health: /health)
cd frontend; npm run dev                 # UI :5000
npm run verify                           # tsc + jest + vite build (бэкенд остановить!)
```

## Гочи (проверено на собственных ошибках)
1. **PowerShell 5.1** ломает кириллицу и ANSI: не писать исходники через `Set-Content`
   (BOM/CRLF → падают Prisma/Jest). Править файлы только редактором.
2. `psql -c "SQL с кавычками"` в PowerShell съедает кавычки → писать SQL в файл (`-f`).
3. Перед `npm run verify` **полностью остановить бэкенд** (nest держит `dist`, сборка падает).
4. `nest build` не удаляет старый `dist` — после переименований делать `rm -rf dist`.
5. `brigade_shifts.date` — тип **DATE**: границы суток считать по UTC-ключу `YYYY-MM-DD`;
   локальный `setHours(0,0,0,0)` уезжает на часовой пояс и диапазон получается пустым (§70).
6. Prisma-миграции: **никогда** не редактировать применённые файлы, только новые.
7. Тестовые данные — с префиксом `audit56_` / `audit57_` и потом вычищать SQL-ом.

## Модель доступа (актуальная)
- Видимость объекта: `object_access` (активный грант) ИЛИ владелец/менеджер компании.
- Чужой объект → **404**, не 403 (не раскрываем существование).
- Цены (`hidePrices = true` или роль `VIEWER`): скрыты в материалах, складе, справочнике
  **и в аналитике**; `prices` не приходят в ответах, суммы — `null`/0.
- Прораб **не может** менять `catalogId` и даты объекта (№219).

## ПЛАН БЛИЖАЙШИХ ШАГОВ (для нового чата)
### Шаг A. №118 — бейдж «объём перевыполнен на N %» на Главной  → раздел §71
**Корень проблемы (найдено 31.10):** `dashboard.service.ts:179` считает
`percent = volume.total_used / volume.spec_quantity` — это **объёмы**, но значение отдаётся
внутри объекта `money` (стр. 269–270), поэтому UI читает `data.money.percent` и подписывает
его как денежный перерасход. Отсюда «864 % перерасхода» на Главной.
`Home.tsx:101–105` уже клампит бар на 100 и рисует `+N% перерасход` красным — то есть
цифра честная, а **формулировка неверная** (объём назван деньгами).
- Сделать: бейдж «объём перевыполнен на N %» (N = round((percent−1)·100)) рядом с прогрессом
  объёмов; бар — по объёмам, красный цвет убрать с объёмов (объём ≠ деньги).
- Деньги показать отдельно: `actual > estimate` → «факт больше сметы на X ₽ (Y %)», иначе —
  «в пределах сметы». Никаких `percent` из блока `money` для денежных подписей.
- Аккуратно: `money.percent` используют `Home.tsx`, `dashboardService.ts` (+ тесты
  `dashboard.week.spec.ts`). Либо оставить поле и переименовать подпись, либо завести
  `volumePercent` и оставить `percent` как deprecated — на решение по объёму правок.
- Тесты: порог (0.99 → нет бейджа, 1.0 → нет, 1.86 → «на 86 %»), деньги отдельно.


### Шаг B. Полный прогон аналитики по ролям → раздел §72
Матрица: **владелец / менеджер / прораб / кладовщик / наблюдатель (hidePrices) / VIEWER /
пользователь без объектов**. Реальные эндпоинты (сверено с контроллерами):
`GET /analytics/summary`, `/analytics/budget-vs-actual`, `/analytics/monthly-trend`,
`/analytics/top-overrun`, `GET /dashboard/summary`.
Что фиксировать:
1. `summary`: суммы vs материалы/склад, пустые данные (объект без смет/склада) — нули, не 500;
2. `budget-vs-actual` при `budget = 0`, `actual > 0` — процент не должен быть `Infinity`/`NaN`;
3. `monthly-trend`: пустые месяцы, границы месяца и часовой пояс (данные за 1-е число);
4. `top-overrun`: сортировка, сколько позиций в топе, деление на ноль;
5. дашборд: `percent` vs реальный перерасход, №118 (после шага A);
6. `hidePrices`: нет `price`/`totalWarehouseValue` (0 или null), корректный
   `warehouseItemsWithoutPrice`, нет утечки через `top-overrun`/`budget-vs-actual`.
Плюс проверить `totalWarehouseValue` и `overrunCount` у наблюдателя.
Итог шага B — **отчёт о расхождениях**, без правок; правки только после «ок».
