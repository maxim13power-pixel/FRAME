## Что это
Учёт стройки: объекты → сметы (проекты) → материалы → склад → бригады (выходы/часы/сделка) →
аналитика и отчёты. Роли: `OWNER`, `MANAGER`, `FOREMAN` (прораб), `STORE_MANAGER`, `VIEWER`.
Плюс наблюдатели — доступ к объекту через `object_access` с флагом `hidePrices`.

Стек: NestJS 11 + Prisma 6 + PostgreSQL 18 (docker, порт **5433**), React 19 + Vite + MUI
(порт **5000**), бэкенд — **3000**.

## Как запускать
```
docker compose up -d                     # БД на 5433
npm --prefix backend run start:dev       # API :3000 (health: /health)
cd frontend; npm run dev                 # UI :5000
npm run verify                           # tsc + jest + vite build (бэкенд остановить!)
```

## Гочи (проверено на собственных ошибках)
1. **PowerShell 5.1** ломает кириллицу и ANSI: не писать исходники через `Set-Content`
   (BOM/CRLF → падают Prisma/Jest). Править файлы только редактором.
2. `psql -c "SQL с кавычками"` в PowerShell съедает кавычки → писать SQL в файл (`-f`).
3. Перед `npm run verify` **полностью остановить бэкенд** (nest держит `dist`, сборка падает).
4. `nest build` не удаляет старый `dist` — после переименований делать `rm -rf dist`.
5. `brigade_shifts.date` — тип **DATE**: границы суток считать по UTC-ключу `YYYY-MM-DD`;
   локальный `setHours(0,0,0,0)` уезжает на часовой пояс и диапазон получается пустым (§70).
6. Prisma-миграции: **никогда** не редактировать применённые файлы, только новые.
7. Тестовые данные — с префиксом `audit56_` / `audit57_` и потом вычищать SQL-ом.
8. **PowerShell 5.1**: `@(Invoke-RestMethod ...)` заворачивает JSON-массив в ОДИН элемент
   (`$x.Count = 1`, `$x[0].id` = строка из всех id) — присваивать без `@()` и перебирать `foreach`.
   Там же нет `$x = if (...) {...} else {...}` (это PS 7+) — писать `if` отдельным оператором.
   Скрипты с кириллицей сохранять в UTF-8 **с BOM**, иначе PS 5.1 читает их как cp1251.
9. **`backend/uploads` целиком не удалять**: там фото реальных пользователей. Чистить только
   строки `material_photos` и файлы, относящиеся к `auditNN_`-данным (иначе теряются живые фото,
   как случилось в §77).
10. **№246**: копии + удаление объекта — в ОДНОЙ транзакции; не выносить клонирование в отдельные
   транзакции (иначе при сбое повторный purge наплодит дубли). Фото-файлы удалять **после** коммита.
   Путь по умолчанию — `process.cwd()/uploads/photos`; при `npm --prefix backend` это
   `backend/uploads/photos` (не `uploads/photos` в корне — проверять оба, если сомневаешься).

## Модель доступа (актуальная)
- Видимость объекта: `object_access` (активный грант) ИЛИ владелец/менеджер компании.
- Чужой объект → **404**, не 403 (не раскрываем существование).
- Цены (`hidePrices = true` или роль `VIEWER`): скрыты в материалах, складе, справочнике
  **и в аналитике**; `prices` не приходят в ответах, суммы — `null`/0.
- Прораб **не может** менять `catalogId` и даты объекта (№219).

## ПЛАН БЛИЖАЙШИХ ШАГОВ (для нового чата)
### Шаг A. №228 — СДЕЛАН (§75), лента на Главной — СДЕЛАНА (§77)
Фото снимаются/грузятся из UI, сжимаются на клиенте, открываются на весь экран; на Главной —
горизонтальная лента «Фото с объектов» (`GET /photos/recent`). Осталось проверить **глазами
в браузере** и HEIC с реального iPhone (смоук на телефоне).

### Шаг B. Квоты и биллинг фото (следующая продуктовая итерация)
- Хранить фото в **S3 Timeweb** (`PhotoStorage` уже за интерфейсом): 1 ₽/ГБ/мес, трафик 100 ГБ
  бесплатно. Диск Amvera — только для разработки: 7 ГБ в тарифе 490 ₽, сверх — 35 ₽/ГБ.
- Ориентир: `1 фото ≈ 0,38 МБ (фото + миниатюра)` → **1 ГБ ≈ 2 600 фото**.
- Модель: квота в тарифе (например, 1–2 ГБ), пакеты докупки (+10 ГБ ≈ 149–199 ₽/мес),
  предупреждение на 80 %, на 100 % — блокировка загрузки (просмотр остаётся), без молчаливого
  удаления. Автосписания на старте не включать.
- Метрика уже есть: `sizeBytes` в `material_photos` — суммировать по владельцу/объекту.

### Шаг C. Технические хвосты фото
1. **Осиротевшие файлы**: при удалении материала/проекта строки уходят каскадом, файлы на диске

## Правила работы (как ведём этот проект)
- Один раздел `PROJECT_STATUS.md` на итерацию, номер = номер коммита (`№NNN`).
- Перед коммитом:
  • правки ТОЛЬКО во фронтенде — `npx tsc -b` + `npm --prefix frontend run build` (бэкенд НЕ трогаем,
    не останавливаем: ~20 с вместо полного verify);
  • есть изменения бэкенда — Jest + `tsc --noEmit` + `npm run verify` (бэкенд остановить, потом поднять).
  Полный `npm run verify` — обязательно перед пушем/релизом.
- Живые проверки — PowerShell-скриптом в `%TEMP%`, результат обязательно смотреть глазами;
  после прогона вычищать тестовые данные SQL-ом.
- Не выдумывать числа: если проверка не доведена — так и писать «не доведено».
