## 1. Что это за проект

PROJECT FRAME — SaaS для строительных смет: объекты → проекты → сметы (материалы/работы),
фиксации объёмов, склады, бригады, аренда, справочники цен, отчёты, аналитика.

- Backend: NestJS + Prisma 5.22 + PostgreSQL (`127.0.0.1:5433`, БД `frame_db`), порт **3000**.
- Frontend: React 19 + MUI 6 + Vite, порт **5000**.
- Репозиторий: `C:\PROJECTS\frame-app`.
- Владелец говорит по-русски; интерфейс, комментарии и коммиты — на русском.

## 3-бис. Что сделано в блоке №380–387 (24.11.2026)

- **SQL-агрегаты** (№380): `objects.findAll`, `projects.findAllByObject` и `findOne` больше не
  выгружают строки материалов — количество и суммы считает `material.groupBy` в

  остаются с нулями; контракт ответа прежний. Регрессия: +2 проверки (итоги числами, список =
  карточка). `scripts/api-regression.js` теперь по умолчанию `127.0.0.1` (на Windows `localhost`
  → ::1 → ECONNRESET).
- **Содержимое PDF** (№381): `buildReportDocDefinition` + юнит-тест маскировки; в регрессии текст
  реального PDF извлекается `pdf-parse` (dev-зависимость backend): `%PDF-`, размер, «Итого»,
  имя отчёта, отсутствие цены 12345. Раздел 14 регрессии переписан (было 167 символов U+FFFD).
- **Границы XLSX-лимитов** (№382): «ровно лимит проходит / +1 отклоняется» на 25 МБ, 10 МБ,
  коэффициент 120, 300 файлов, лист 20 000 × 256, 30 листов, sharedStrings 100 000 и 5 МБ;
  ZIP64 и `compressed = 0` зафиксированы тестами.
- **Длинная смета** (№383): окно 200/50 + «Показать ещё» + «Показать все» (>1000 — подтверждение)
  + «Страница N из M» с прыжком; поиск/сортировка/ИТОГО/выделение — по всей смете, нумерация
  и Shift-диапазон сквозные; печать из браузера с галочкой «только текущую страницу»;
  PDF — футер «Стр. X из Y»; прайс грузится одним запросом вместо двух.
  Проверено в реальном браузере (headless Chrome): 200 строк — «Страница 1 из 1»,
  450 строк — 3 страницы с прыжком, поиск строки с 3-й страницы, счётчик «Найдено: N из M».
- **№384 — размер страницы и навигация**: дефолт 50/25 + селектор 25/50/100/200 с памятью,
  липкий мини-пейджер «‹ 1 / N ›», круглая кнопка «вниз» к ИТОГО (исчезает у футера).
  Проверено в headless Chrome.
- **№386 — мобилка**: автодогрузка УБРАНА (список больше не растёт сам, плашка страниц
  не «убегает»); «вниз» не скрывается при скролле вниз и прокручивает с запасом под
  фиксированные нижние панели — кнопки плашки видны целиком.
- **№387 — низ списка**: при достижении низа плашка итогов и FAB выезжают (раньше только
  при скролле вверх); нижний отступ списка 190 px, чтобы они не накрывали кнопки
  «Показать ещё / Показать все».
- **№385 — мобильные ширины и лишний xlsx**: шаблон импорта грузится лениво (×lsx больше
  не попадает в чанк сметы, предупреждение про `stream` исчезло); убран `body min-width: 320px`;
  шапка сжимается на xs и прокручивается ниже 320; плашка итогов переносит строки;
  FAB «+» и «вниз» скрываются при скролле вниз.

## 5. Особенности окружения

- Backend в watch (`npm run start:dev`). Не убивать дочерний процесс по одиночному PID —
  только `taskkill /PID <pid> /T /F` по процессу `npm-cli.js run start:dev`.
- Перед `prisma generate` backend нужно остановить (Windows блокирует файлы клиента).
- `DATABASE_URL` — только `127.0.0.1`, не `localhost` (иначе P1001).
- Схему меняли с остановкой backend: `prisma db push --accept-data-loss` (снят старый unique
  `[name, kind]`) + `generate` + миграция категорий + `start:dev`.
- Для production: свежая резервная копия + проверенный diff миграции, без `db push` как есть.
