## 1. Что это за проект

PROJECT FRAME — SaaS для строительных смет: объекты → проекты → сметы (материалы/работы),
фиксации объёмов, склады, бригады, аренда, справочники цен, отчёты, аналитика.

- Backend: NestJS + Prisma 5.22 + PostgreSQL (`127.0.0.1:5433`, БД `frame_db`), порт **3000**.
- Frontend: React 19 + MUI 6 + Vite, порт **5000**.
- Репозиторий: `C:\PROJECTS\frame-app`.

## 5. Особенности окружения

- Backend в watch (`npm run start:dev`). Не убивать дочерний процесс по одиночному PID —
  только `taskkill /PID <pid> /T /F` по процессу `npm-cli.js run start:dev`.
- Перед `prisma generate` backend нужно остановить (Windows блокирует файлы клиента).
- `DATABASE_URL` — только `127.0.0.1`, не `localhost` (иначе P1001).
- **Схема БД меняется ТОЛЬКО миграциями** (⭐ №394): dev переведён на `_prisma_migrations`,
  `prisma/migrations/0_init` — baseline. Новая миграция: `npx prisma migrate dev --name ...`;
  применить на базе: `npx prisma migrate deploy`; проверить: `npx prisma migrate status`.
  `prisma db push` (и тем более `--accept-data-loss`) на базах с данными больше не использовать.
  Подробности и три сценария baseline — `docs/MIGRATIONS.md`.
- Для production: свежая резервная копия (`pg_dump -Fc`) + проверенный restore + `migrate deploy`;
  откат схемы — только восстановлением дампа (down-миграций у Prisma нет).

- Уборка тестового пользователя: сначала `priceCatalog.deleteMany({ where: { ownerId } })` —
  иначе `price_catalogs_ownerId_fkey` (`onDelete: Restrict`), затем `user.delete`.
  Регистрация также создаёт личный демо-объект «Квартира-образец» — после удаления пользователя
  он остаётся сиротой, поэтому удаляйте объекты, созданные тестовым пользователем, вместе с ним
  (проверять `object.count()` до/после).
- Разделы, скрытые флагом в `frontend/src/App.tsx`: `/reports` («Отчёты временно скрыты»),
  пунктов нет в меню — экран недоступен даже по прямому URL (редирект на «Главную»).
  Не включать без решения владельца; API при этом полностью рабочий.

**Почему такой порядок, а не как в списке владельца:** биллинг нельзя ставить последним —

обещает то, чего нет; но и до прод-контура его делать нельзя — принимать деньги на
непроверенной инфраструктуре (без бэкапов/алертов/restore drill) рискованно. RuStore —
самый длинный внешний трек, его лучше запускать параллельно этапу 1–3, а не после релиза сайта.
