# Мониторинг ошибок и алерты (Telegram)

> ⭐ №396, 25.11.2026. Решение владельца: на этапе запуска — **Telegram, без Sentry**.
> Смысл: любая 5xx-ошибка API, падение процесса и ошибка в браузере приходят в канал,
> а не «узнаём от клиента через неделю».

## Что уже работает

| Источник | Когда срабатывает | Где живёт |
|---|---|---|
| Ошибки API (5xx) | глобальный фильтр исключений | `backend/src/common/filters/alerting-exception.filter.ts` |
| Падение процесса | `uncaughtException`, `unhandledRejection` | `backend/src/main.ts` (`installFatalHandlers`) |
| Ошибки браузера | `window.onerror`, `unhandledrejection` | `frontend/src/utils/errorReporter.ts` → `POST /telemetry/client-error` |
| Приём телеметрии | публичный эндпоинт (без токена), лимиты на IP и общий | `backend/src/telemetry/*` |
| Отправка в Telegram | сервис с антифлудом | `backend/src/common/alerts/telegram-alerts.service.ts` |

Фильтр **не меняет ответы API** (наследует `BaseExceptionFilter`): фронт получает те же
`{ statusCode, message }`, что и раньше, а алерт просто уходит «сбоку». Ошибки 4xx (валидация,
права) в канал **не** шумят — только 5xx и падения.

## Настройка (5 минут)

1. Создайте бота: в Telegram напишите **@BotFather** → `/newbot` → имя и username.
   Получите токен вида `123456789:AA...`.
2. Создайте канал (или группу) для алертов. **Приватный**: там будут технические подробности.
3. Добавьте бота в канал администратором (иначе он не сможет писать).
4. Узнайте id чата: удобнее всего создать канал и открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` после любого сообщения в канал,
   либо добавить в канал бота **@username_to_id_bot**. Для каналов id начинается с `-100`.
5. Пропишите в `backend/.env` (и в панели Amvera для прода):

```env
# ⭐ №396: алерты об ошибках в Telegram (без них мониторинг молча выключен)
TELEGRAM_ALERT_BOT_TOKEN=123456789:AA...
TELEGRAM_ALERT_CHAT_ID=-1001234567890
# необязательные настройки:
# TELEGRAM_ALERT_WINDOW_MS=300000      # окно антифлуда, мс (по умолчанию 5 минут)
# CLIENT_ERROR_LIMIT_PER_MIN=5         # сколько ошибок браузера принимать с одного IP в минуту
# CLIENT_ERROR_LIMIT_TOTAL_PER_MIN=30  # общий лимит, чтобы не завалить канал
# APP_ENV=production                   # попадёт в заголовок сообщения
```

6. Перезапустите бэкенд. В логе появится `алерты об ошибках включены (Telegram)`.
7. Проверка: `curl -X POST <API>/telemetry/client-error -H "Content-Type: application/json" -d '{"message":"проверка алертов"}'`
   → в канале должно появиться сообщение «🚨 … Ошибка в браузере».

Без `TELEGRAM_ALERT_BOT_TOKEN`/`CHAT_ID` сервис **молча выключен** — dev и тесты работают как
раньше, ничего не отправляется.

## Антифлуд и лимиты (почему их три)

1. **Ключ ошибки в сервисе алертов**: одна и та же ошибка (маршрут + текст) уходит не чаще
   окна (5 минут). Если за окно она повторилась — в следующем сообщении будет
   «🔁 повторилось N раз(а)».
2. **Лимит на IP** (`CLIENT_ERROR_LIMIT_PER_MIN`, 5/мин) — публичный эндпоинт, чтобы один
   «весёлый» браузер не занял канал.
3. **Общий лимит** (`CLIENT_ERROR_LIMIT_TOTAL_PER_MIN`, 30/мин) — предохранитель на случай
   массового сбоя у многих пользователей: лучше потерять часть сообщений, чем получить бан от
   Telegram за флуд.

Ответ у эндпоинта всегда **204** — клиент не должен знать, приняли ошибку или отбросили.

## Что уходит и что НЕ уходит

Уходит: текст ошибки, стек (до 8 строк), путь страницы (`/objects/1/...`, без query),
user-agent, IP, окружение, время.

**Не уходит**: тело запросов, e-mail/телефоны, токены, содержимое смет. Поэтому канал можно
держать техническим, но всё равно лучше приватным.

## Проверка без реального Telegram

`TELEGRAM_ALERT_API_BASE` можно направить на локальный фейк — так проверялась цепочка
«ошибка → сервис → HTTP-запрос» (см. `PROJECT_STATUS`, №396): поднять заглушку на :3099,
запустить второй экземпляр бэкенда с `PORT=3101` и этими env, отправить ошибку, посмотреть
тело запроса. Реальный чат для этого не нужен.

## Что дальше (когда появится бюджет/желание)

- Sentry (или GlitchTip) — группировка, «сколько пользователей задело», релизы, source maps.
  Telegram останется как быстрый канал: он не заменяет трекер, но мгновенно показывает «что-то
  сломалось».
- Аптайм-мониторинг (healthcheck извне) — Telegram-алерты не заметят, если сервер просто лежит
  и не пишет ошибок. Кандидаты: UptimeRobot (бесплатный тариф), свой cron + curl.
- Алерты по метрикам (медленные запросы, рост 5xx) — после переезда на прод.
