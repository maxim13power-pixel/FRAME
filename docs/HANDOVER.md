## 2. Изменения в модели данных (Prisma)

```prisma
model PriceCatalog {              // ⭐ №151
  id, name, ownerId?              // ownerId = null → системный (демо), доступен всем
  isArchived Boolean @default(false)
  items PriceItem[]  projects Project[]
}
PriceItem.catalogId Int           // обязательный, ON DELETE CASCADE
Project.catalogId   Int?          // справочник проекта (по умолчанию для сметы)
```

Миграция: `backend/prisma/migrations/20261022183410_add_price_catalogs` — **с backfill**:
общие расценки → «Демо-справочник», личные → личный справочник владельца.
Проверено локально: `Демо-справочник` 306 расценок, `Личный справочник` (user 2) 3 расценки, NULL нет.

**Выгрузка смет** теперь содержит скрытый лист `_meta`: `frameExport=1`, `columnsVersion=1`,
`projectId`, `projectName`, `objectName`, `exportedAt`, `includePrices`. По нему импорт узнаёт
наш файл и не просит маппинг колонок (проверено round-trip: 3 позиции с ценами прочитаны).

**Права:** системный справочник правит/архивирует только ADMIN; в системный **нельзя** добавлять
расценки; чужой личный справочник недоступен. Общие расценки (`ownerId=null`) правит только ADMIN
(№149). Наблюдатель (VIEWER) не может создавать/фиксировать.

## 3. Принятые решения по импорту смет (ответы владельца)

1. **Q1** Прораб заливает смету **без согласования** заказчика → прямой commit + `AuditLog`.
2. **Q2** При расхождении цен **истина = цена из файла**; расхождение со справочником — предупреждение.
3. **Q3** Несколько **справочников цен** под объекты («Квартиры/Коттеджи», «Склад X5»); при ручном
   вводе строки — выбор справочника (по умолчанию справочник проекта, можно взять из другого).
4. **Q4** Лимит **500 строк**; начинаем с **шаблона + нашей выгрузки + вставки из буфера**;
   приём чужих файлов «как есть» — **не делаем** (дорого, неполно, вечная поддержка).
5. **Q6** `.xls` — **отказ** с подсказкой «Сохраните как .xlsx» (exceljs не читает BIFF8).
6. **Q7** Одна строка = одна работа + один материал; «работа + N материалов» = N строк,
   работа только в первой. Цена `0` — это **осознанно** (бесплатно/учтено), «занижена» только
   когда цены **нет** (пусто ≠ 0).
7. **Q9** Протокол `.xlsx` после импорта — во втором срезе.
8. **Q8 / идея владельца** Загрузка **нашей же выгрузки** другим пользователем (заказчик собирает
   расчёты от нескольких прорабов) — **делаем**, основа уже есть (маркер №152).
9. **Идея владельца** Чекбокс **«Перенести прогресс выполнения»** в предпросмотре: появляется только
   если перенос возможен (наш файл + есть факт > 0 + нет фиксаций по тем же позициям в проекте),
   с инлайн-пояснением, что переносятся факт, **% выполнения** и запись в истории.
   Технически — **создавать фиксацию** («перенос из файла»), а не писать число в `totalUsed`:
   `totalUsed` — накопитель (`newTotal = totalUsed + amount`), иначе прогресс поедет.
10. **ЛСР (ГРАНД-Смета)** — отдельной задачей позже и **целевым парсером**, а не универсальным
    маппингом (в ЛСР нет отдельных цен материалов, есть НР/СП и коэффициенты).

## 4. Что делать дальше (план, в этом порядке)

**Справочники — осталось:**
1. **Привязка справочника к проекту** (`Project.catalogId`): при создании/редактировании проекта —
   модалка «Справочник цен» с названием, **подставленным из имени объекта и редактируемым**,
   + «выбрать существующий» / «создать новый» (в `PriceCatalogList` уже есть проп `defaultNewName`).
2. **Смета по умолчанию работает в справочнике проекта**; в шапке сметы — видимый бейдж
   «Справочник: …», чтобы было понятно, откуда цены.
3. **В форме добавления строки сметы** — селектор справочника + поиск расценки **внутри выбранного**
   (сейчас `searchPriceItems` ищет по всем доступным).
4. **«Сохранить смету как справочник»** — создать справочник из сметы проекта.

**Импорт, срез 1 (после справочников):**
5. Кнопка «Загрузить смету» + страница импорта: dropzone (xlsx/csv) + «вставить из буфера» (TSV).
6. Серверный парсер (exceljs уже есть): распознавание **нашей выгрузки** по `_meta` + наш шаблон;
   разбор листа «Материалы» (двухуровневая шапка, пропуск «ИТОГО», игнор «Посменной сводки»).
7. Предпросмотр: сопоставление расценок (артикул → нормализованное название+ед. → подсказка),
   дубли (`externalKey`), режимы цен («из файла» / «из справочника» / «без цен»),
   выбор справочника или «создать из файла».
8. **Чекбокс «Перенести прогресс»** (см. п. 9 выше).
9. Commit одной транзакцией + `ImportBatch` (журнал партий) + `AuditLog`.

**Срез 2:** откат импорта, протокол `.xlsx`, история партий, повторный импорт с диффом.

## 5. Как работать в этом репозитории (шпаргалка)

- Проверка перед сдачей: `npm run verify` (backend `nest build` + frontend `tsc -b && vite build`).
- Линт: `cd frontend; npx eslint <файлы>` (в проекте есть старые предупреждения — не пугаться).
- Дев-серверы: `npm --prefix backend run start:dev` (:3000) и `npm --prefix frontend run dev` (:5000).
- БД локально: миграции ведутся (`_prisma_migrations` заполнена) → `npx prisma migrate dev`.
  **EPERM на `prisma generate`** = запущен node → `taskkill /F /IM node.exe`, затем generate и заново поднять дев-серверы.
- Образцы реальных смет — в `docs/samples/` (**в git не уезжают**, см. `.gitignore`):
  Х5 (простая), ВОР Самара (двухуровневая шапка + строка номеров колонок),
  ЛСР ГРАНД-Смета (1751×281, 1563 merges), `.xls`-калькуляция (BIFF8).
- Git-ритуал владельца: работа на ветке `cline-*`, затем
  `git checkout main; git merge --no-ff <ветка> -m "Merge №N: суть"; git push`.
  PowerShell < 7 → команды через `;`, **не** `&&`. Файлы в рабочей копии с CRLF: многострочные
  замены в редакторе могут не совпадать — использовать однострочные анкоры или вставку по номеру строки.
- Экспорт XLSX: `frontend/src/utils/xlsxStyle.ts` (движок оформления),
  `materialsWorkbook.ts` (сборка книги + маркер `_meta`), `exportMaterials.ts` (writeFile + PDF),
  `exportWarehouse.ts` (склад).
- Уведомления/подтверждения: `frontend/src/contexts/FeedbackContext.tsx` → `useFeedback()`:
  `notify/success/error` (снекбар) и `confirm()` (стилизованный диалог, `Promise<boolean>`).
- Справочники цен: бэкенд `backend/src/price-list/price-list.service.ts` (+ `dto/create-catalog.dto.ts`),
  фронт `frontend/src/components/PriceCatalogList.tsx`, роуты `/price-list`, `/price-list/:catalogId`.
- Шаблоны смет: `backend/src/estimate-templates/*`, фронт `Projects.tsx` (сохранить/применить)
  и кнопка «Добавить из шаблона» в `Materials.tsx`.
